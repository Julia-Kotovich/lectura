# Workshop speaking script (~2 minutes)

Use this after a short ProfDeck demo (or with 1–2 UI screenshots). Goal: invite professors into a focused discussion, not a long Q&A dump.

---

Hi everyone — thank you. I’ll keep this short and then ask for your expertise.

**ProfDeck** is an AI-assisted system for turning learning objectives / syllabus material into draft lecture slides for Software Engineering courses. We don’t claim the decks are classroom-ready yet. In our human evaluation, Correctness was relatively strongest, while Clarity and Ready-to-teach were the main bottlenecks. Automatic Bloom alignment can improve, but that does **not** automatically mean a professor would teach from the deck after light edits.

So the open question for this workshop is practical:

> What should we improve first so that AI lecture drafts become actually usable for real teaching?

I’d love your input on a few concrete points:

1. When you open an AI-generated deck, what do you check first?
2. Where would AI help you most: full course, one lecture, or fixing one weak section?
3. Which slide types are non-negotiable in a good SE lecture?
4. Is Bloom’s taxonomy useful in your real prep workflow — or mostly theoretical?
5. What would be a fair baseline to compare against: plain ChatGPT, your old slides, or an open reference course?

If you prefer writing, there is a one-page questionnaire — please mark priorities and leave one experiment you’d want us to run next.

Thanks — I’m especially interested in harsh, concrete feedback.

---

## Timing tips

| Block | Time |
|-------|------|
| What ProfDeck is + honest result | ~45–60s |
| Ask 3–5 questions | ~45–60s |
| Hand off to discussion / questionnaire | ~15–20s |

If time is very short, ask only:

1. What do you check first?
2. Course vs lecture vs section?
3. One experiment for the next paper?
