# Reference Structure for an OOP Course (Bachelor Level, European University)

Use the following structure as the DEFAULT educational framework when generating Computer Science lectures and slides for a semester-based university course.

The AI system should understand that:

- the course lasts 1 semester,
- students are undergraduate Computer Science students,
- there is:
  - 1 lecture per week,
  - 1 practical/lab session per week,
- each lecture lasts 1 hour,
- the course should follow progressive complexity growth,
- practical sessions reinforce lecture concepts,
- lectures are conceptual,
- labs are implementation-focused.

## Course Type

Object-Oriented Programming (OOP)

## Audience

Bachelor students in Computer Science

## Semester Length

12–14 teaching weeks

## Weekly Format

- 1 × Lecture (60 minutes)
- 1 × Practical/Lab Session (60–120 minutes)

## Educational Philosophy

The lecture should: introduce concepts, explain theory, demonstrate examples, build intuition, connect concepts together.

The practical session should: reinforce through coding, hands-on exercises, debugging, gradually increasing complexity.

Maintain continuity between lecture topics, lab exercises, homework, and future lectures.

## Recommended Weekly Lecture Structure (1 Hour)

1. **Introduction & Context** (5 min)
2. **Core Theory Block #1** (10–15 min)
3. **Guided Example / Visualization** (5–10 min)
4. **Core Theory Block #2** (10–15 min)
5. **Interactive Thinking Segment** (5 min)
6. **Real-World Engineering Context** (5 min)
7. **Summary & Transition** (5 min)

## Practical / Lab Session Structure

1. Warm-up (10–15 min)
2. Guided Coding (20–30 min)
3. Independent Task (20–40 min)
4. Review & Reflection (10 min)

## Example Semester (OOP)

| Week | Lecture | Lab |
|------|---------|-----|
| 1 | Introduction to Programming Paradigms & OOP | Environment setup + first classes |
| 2 | Classes and Objects | Build simple object models |
| 3 | Encapsulation & Access Modifiers | Refactor into encapsulated structures |
| 4 | Constructors & Object Lifecycle | Design multi-object systems |
| 5 | Inheritance | Build inheritance hierarchies |
| 6 | Polymorphism | Dynamic dispatch exercises |
| 7 | Interfaces & Abstract Classes | Design flexible architectures |
| 8 | Composition vs Inheritance | Refactor using composition |
| 9 | Exception Handling | Build resilient applications |
| 10 | Collections & Generics | Data-driven applications |
| 11 | SOLID Principles & Design Patterns | Clean architecture |
| 12 | Mini Project Architecture | Project consultations |
| 13 | Project Presentations / Review | — |

## Slide Generation Rules

- 18–30 slides per 1-hour lecture
- ~40% conceptual, 30% visuals, 20% code, 10% recap/questions
- Max 1–3 concepts per lecture; slides are part of a coherent course, not isolated artifacts
