public class ConfigManager {
    private static volatile ConfigManager instance;
    private Properties config;
    
    private ConfigManager() {
        config = loadConfiguration();
    }
    
    public static ConfigManager getInstance() {
        if (instance == null) {
            synchronized (ConfigManager.class) {

                }
            }

    }
}

Adapter Pattern: Interface Conversion

Understand
Bloom evidence: Slide presents Adapter intent, structure, and variants through bullets and diagram without requiring students to apply, analyze, or evaluate—primarily explanatory content.
bullets
  • Intent: Convert incompatible interfaces
  • Wraps existing class with new interface
  • Two variants: Class and Object Adapter
  • Enables reuse without modification
diagram

Prompt: UML diagram showing Client using Target interface, Adapter implementing Target and containing Adaptee reference, and Adaptee class with incompatible interface. Show delegation arrow from Adapter to Adaptee with 'adaptee.specificRequest()' label.

Speaker notes

Adapter makes incompatible interfaces work together—like a power adapter converting US plug to European socket. The Adapter implements the interface the client expects (Target) and wraps the existing class (Adaptee). Object Adapter uses composition (shown here)—more flexible, can adapt multiple adaptees. Class Adapter uses multiple inheritance—more efficient but less flexible. Real example: Java's InputStreamReader adapts byte streams to character streams. Use when you can't modify existing code but need it to work with new interface.

Composite Pattern: Part-Whole Hierarchies

Understand
Bloom evidence: Slide explains Composite intent, roles, and structure through bullets and diagram without requiring application or analysis—conceptual introduction level.
bullets
  • Intent: Compose objects into tree structures
  • Treat individual and composite objects uniformly
  • Recursive composition
  • Component, Leaf, Composite roles
diagram

Prompt: UML diagram showing Component interface with operation(), Leaf implementing Component, and Composite implementing Component with children list and add/remove methods. Show tree structure with Composite containing both Leaf and other Composite objects.

Speaker notes

Composite represents part-whole hierarchies as trees. Classic example: file system with files (leaves) and directories (composites containing files and other directories). The key insight: clients treat leaves and composites uniformly through Component interface. Composite stores children and delegates operations to them recursively. This enables building complex structures from simple parts. The pattern embodies recursion—composites can contain other composites. GUI frameworks use this extensively: panels contain buttons, labels, and other panels.

Decorator Pattern: Dynamic Responsibilities

Understand
Bloom evidence: Slide presents Decorator intent, wrapping mechanism, and stacking capability through bullets and diagram without hands-on application—explanatory content.
bullets
  • Intent: Add responsibilities dynamically
  • Flexible alternative to subclassing
  • Decorator wraps component
  • Multiple decorators can be stacked
diagram

Prompt: UML diagram showing Component interface, ConcreteComponent implementing it, Decorator implementing Component and containing Component reference, ConcreteDecoratorA and ConcreteDecoratorB extending Decorator. Show wrapping relationship with nested boxes visualization.

Speaker notes

Decorator adds behavior to objects dynamically without subclassing. Decorator implements same interface as component it wraps and contains reference to component. It forwards requests to wrapped component, adding behavior before/after. Multiple decorators can be chained. Classic example: Java I/O streams—BufferedInputStream wraps FileInputStream, which might wrap another stream. Coffee shop analogy: plain coffee decorated with milk, sugar, whipped cream. Each decorator adds cost and functionality.
